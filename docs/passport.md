# Паспорт проекта «ООП-прототип агента умного дома»

**Направление:** Умный дом (выбрано на весь модуль)
**Название:** ООП-прототип агента умного дома
**Дата старта:** 07.10.2026

## 1. Проблема
В квартире/доме устройства работают разрозненно: отопление, свет, датчики движения и дверей не связаны друг с другом. Человек вручную регулирует температуру и свет, забывает выключить свет в пустых комнатах, поздно замечает открытую дверь или перегрев/переохлаждение. Это приводит к дискомфорту, перерасходу электроэнергии и рискам безопасности.

## 2. Цель проекта
Создать к концу модуля ООП-прототип интеллектуального агента, который по показаниям датчиков (время, комната, температура, освещённость, движение, дверь, режим контроллера) принимает решения: регулировать климат, управлять светом, сигнализировать о событиях.

## 3. Задачи
1. Описать предметную область и зафиксировать паспорт проекта.
2. Создать структуру репозитория: `data/`, `src/`, `tests/`, `docs/`.
3. Подготовить стартовый набор синтетических данных `smart_home_events_raw.csv`.
4. Спроектировать классы агента (SensorEvent, Room, SmartHomeAgent, Controller) — следующий проектный час.
5. Реализовать прототип агента на ООП и покрыть его тестами.
6. Вести бэклог из 3-5 карточек на канбан-доске и фиксировать прогресс в Git.

## 4. Продукт
- Паспорт проекта (этот документ)
- Структура папок проекта
- Файл `data/smart_home_events_raw.csv` — первичные показания датчиков
- Бэклог `docs/backlog.md`
- В будущем: код агента в `src/` + тесты в `tests/`

Кому полезен: жильцам (комфорт + экономия), студенческой команде (учебный прототип ООП-агента), преподавателю (проверяемый артефакт по теме).

## 5. Ограничения будущего агента
- Данные синтетические, всего ~20-30 строк на старте, без реального железа.
- Агент работает только с заданными полями CSV, без камер/микрофонов.
- Нет сети и облака — только локальная логика.
- Решение реактивное (если-то), без ML на первом этапе.
- Один контроллер на весь дом, режимы: `auto`, `eco`, `manual`, `away`.
- Python + стандартная библиотека, ООП-подход обязателен.

## 6. Входные данные
Файл `data/smart_home_events_raw.csv`, колонки:
- `timestamp` — время события, ISO-формат, напр. 2026-10-07T08:00:00
- `room` — комната: living_room / bedroom / kitchen / hallway / bathroom
- `temperature` — температура, °C, float (16.0–28.0)
- `light_lux` — освещённость, люкс, int (0–800)
- `motion` — движение: 0 / 1
- `door` — состояние двери: open / closed
- `mode` — режим контроллера: auto / eco / manual / away

## 7. Почему выбран «Умный дом»
- Понятные данные без спецзнаний логистики/геймдизайна.
- Легко показать преподавателю: таблица + логика «если никого нет — выключи свет».
- Сильные стороны vs других: простой CSV, наглядные классы (Датчик, Комната, Агент).
- Слабые стороны других отклонили: доставка требует карт/координат, игра — игрового движка.
- Причина зафиксирована письменно здесь для отчёта по форме.
